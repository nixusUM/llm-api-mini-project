# Руководство по векторным базам данных

## Введение

Векторные базы данных стали ключевым компонентом современных AI-приложений. Они позволяют хранить и эффективно искать высокоразмерные векторные представления — эмбеддинги.

## Что такое векторная база данных

Векторная база данных — это система управления данными, оптимизированная для хранения и поиска многомерных векторов. В отличие от традиционных реляционных баз, которые работают со структурированными таблицами, векторные БД работают с плотными числовыми представлениями.

### Ключевые особенности

- Хранение высокоразмерных векторов (обычно 384-1536 измерений)
- Быстрый приближенный поиск ближайших соседей (ANN)
- Поддержка различных метрик расстояния (косинусное, евклидово, dot-product)
- Масштабируемость на миллиарды векторов

## Архитектура векторных БД

### Компоненты системы

1. **Storage Engine** — отвечает за физическое хранение векторов
2. **Index Builder** — создает индексы для быстрого поиска
3. **Query Processor** — обрабатывает поисковые запросы
4. **Metadata Store** — хранит дополнительную информацию о векторах

### Алгоритмы индексации

Самые популярные алгоритмы приближенного поиска:

- **HNSW** (Hierarchical Navigable Small World) — графовый алгоритм с высокой точностью
- **IVF** (Inverted File Index) — кластеризация пространства
- **PQ** (Product Quantization) — сжатие векторов
- **LSH** (Locality-Sensitive Hashing) — хеширование для приближенного поиска

## Популярные векторные БД

### Pinecone

Pinecone — полностью управляемый облачный сервис. Особенности:
- Нет необходимости управлять инфраструктурой
- Автоматическое масштабирование
- Гибридный поиск (векторный + метаданные)

### Weaviate

Weaviate — open-source векторная база с графовой моделью:
- Поддержка модульной архитектуры
- Интеграция с различными embedding-моделями
- GraphQL интерфейс

### Milvus

Milvus — разработка LF AI & Data Foundation:
- Распределенная архитектура
- Поддержка GPU-ускорения
- Интеграция с Kubernetes

### Chroma

Chroma — легковесная embedded база для прототипирования:
- Простая интеграция в Python-приложения
- Поддержка клиент-серверного режима
- Минимальные зависимости

### Qdrant

Qdrant — высокопроизводительная БД на Rust:
- Фильтрация по метаданным во время поиска
- Сериализация в BSON
- Гибкие настройки индекса

## Применение в RAG-системах

Retrieval-Augmented Generation (RAG) — основной паттерн использования векторных БД. Архитектура типичного RAG-приложения:

### Этап индексации

1. Загрузка документов из различных источников
2. Разбиение на чанки (chunking)
3. Генерация эмбеддингов через API (OpenAI, Cohere) или локальные модели
4. Сохранение в векторную базу с метаданными

### Этап ретривала

1. Получение запроса от пользователя
2. Преобразование запроса в эмбеддинг
3. Поиск ближайших соседей в БД
4. Ранжирование результатов
5. Возврат top-k релевантных чанков

### Этап генерации

1. Конструирование промпта с retrieved контекстом
2. Вызов LLM с расширенным контекстом
3. Генерация ответа с учетом retrieved информации

## Оптимизация производительности

### Размер чанков

Оптимальный размер чанка зависит от:
- Типа документов (код, статьи, диалоги)
- Модели эмбеддингов (max sequence length)
- Типа запросов (конкретные vs общие)

Рекомендуемые диапазоны:
- Короткие чанки (128-256 токенов) — для точного поиска
- Средние чанки (512 токенов) — универсальный вариант
- Длинные чанки (1024+ токенов) — для контекстного понимания

### Стратегии chunking

#### Fixed-size chunking

Простое разбиение по фиксированному количеству символов или токенов:
- Преимущества: простота, предсказуемость
- Недостатки: разрыв семантики на границах

#### Semantic chunking

Разбиение по смысловым границам (предложения, абзацы):
- Преимущества: сохранение контекста
- Недостатки: неравномерный размер чанков

#### Sliding window

Перекрывающиеся чанки для сохранения контекста:
- Преимущества: контекст на границах
- Недостатки: увеличение объема данных

## Метрики оценки

### Точность поиска

- **Precision@k** — доля релевантных результатов в top-k
- **Recall@k** — доля найденных релевантных документов
- **MRR** (Mean Reciprocal Rank) — средняя позиция первого релевантного
- **NDCG** — учет позиции и релевантности

### Производительность

- **Latency P50/P95/P99** — время отклика
- **QPS** (Queries Per Second) — пропускная способность
- **Index build time** — время построения индекса
- **Storage efficiency** — компрессия векторов

## Будущее развитие

### Тренды векторных БД

1. **Multi-modal embeddings** — объединение текста, изображений, аудио
2. **Hybrid search** — комбинирование векторного и текстового поиска
3. **Federated search** — распределенный поиск across multiple indices
4. **Real-time indexing** — мгновенное добавление новых документов
5. **Quantum-inspired algorithms** — квантовые алгоритмы для ANN

## Заключение

Векторные базы данных стали неотъемлемой частью AI-инфраструктуры. Выбор конкретной БД зависит от требований к масштабу, производительности и управляемости. Для прототипирования подходят Chroma и FAISS, для production — Pinecone, Weaviate, Milvus или Qdrant.

При проектировании RAG-системы важно уделять внимание не только выбору БД, но и качеству chunking-стратегии, метаданным и оценке результатов.
