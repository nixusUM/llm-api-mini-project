## Проверка качества chunking

### Тест 1: Сравнение стратегий

```bash
# Сравнить стратегии на документе о векторных БД
curl -X POST http://127.0.0.1:5052/api/compare \
  -H "Content-Type: application/json" \
  -d '{
    "document": "sample_documents/01_vector_databases_guide.md"
  }'
```

**Что проверить:**
1. Fixed Size создает более равномерные чанки
2. Structure Based сохраняет границы разделов
3. Structure Based может давать более семантически целостные чанки

### Тест 2: Границы чанков

```
Промпт: "Расскажи про HNSW алгоритм"

С Fixed Size: может разорвать описание на середине
С Structure Based: должен вернуть полный раздел про HNSW
```

### Тест 3: Метаданные

```bash
# После индексации проверить метаданные
curl http://127.0.0.1:5052/api/stats
```

**Ожидаемые поля:**
- chunk_id
- source
- title
- section
- strategy
- embedding_sample

## Сравнение стратегий chunking

### Метрики сравнения

| Метрика | Fixed Size | Structure Based |
|---------|------------|-----------------|
| Средний размер чанка | ~500 chars | Варьируется |
| Размер чанков | Предсказуем | Непредсказуем |
| Семантическая целостность | Может нарушаться | Сохраняется |
| Скорость chunking | Быстрее | Медленнее |
| Покрытие заголовков | Может пропустить | Сохраняет |

### Визуальная проверка

В UI на вкладке "⚖️ Сравнение стратегий":

1. Выберите документ
2. Нажмите "Сравнить стратегии"
3. Проверьте:
   - Количество чанков
   - Разброс размеров (min/max)
   - Примеры чанков — границы должны совпадать с логическими разделами

### Проверка ранжирования

```bash
# Поиск с top_k=5
curl -X POST http://127.0.0.1:5052/api/search \
  -H "Content-Type: application/json" \
  -d '{
    "query": "asyncio python",
    "strategy": "fixed_size",
    "top_k": 5
  }'
```

**Проверка:**
- Score должен уменьшаться от 1-го к 5-му результату
- Все результаты должны быть из соответствующих документов

## Сохранение и загрузка индекса

### Тест сохранения

```bash
curl -X POST http://127.0.0.1:5052/api/save_index \
  -H "Content-Type: application/json" \
  -d '{
    "strategy": "fixed_size",
    "storage": "json"
  }'
```

**Проверка:**
- Файл создан в document_indices/
- JSON содержит entries с embedding и metadata

### Формат сохраненного индекса

```json
{
  "dimension": 1536,
  "entries": [
    {
      "chunk_id": "01_vector_databases_guide.md_fixed_0",
      "text": "...",
      "embedding": [0.1, 0.2, ...],
      "source": "01_vector_databases_guide.md",
      "title": "Руководство по векторным базам данных",
      "section": "chunk_0",
      "strategy": "fixed_size",
      "metadata": {...}
    }
  ]
}
```

## Первый RAG-запрос

1. В блоке **Первый RAG-запрос** галереи основного веб-приложения задайте вопрос и количество Top-k (4-6).
2. Нажмите **Сравнить режимы** — под формой появятся ответы:
   - без ретрива (LLM отвечает только по запросу),
   - с RAG (LLM плюс извлечённые чанки с пояснениями и источниками).
3. Проверьте, что RAG-ответ:
   - опирается на источники, перечисленные в разделе `Источники`,
   - упоминает одни и те же темы, которые ожидаются для контрольного вопроса.
4. Используйте таблицу из 10 контрольных вопросов ниже:
   - Каждый вопрос показывает, что следует ожидать от ответа и какие документы использовать.
   - Кнопка «Проверить» запускает сравнение сразу по выбранному вопросу.
   - Сравните качество респондентов с RAG и без, фиксируя соответствие ожиданиям.
